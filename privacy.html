Privacy Policy

Effective 31 July 2026 · Applies to the Perde Android app (app.perde) and this website

Perde collects nothing. It does not gather, store, or transmit any personal data, and it has no user accounts.

This is not a promise resting on good intentions. The app does not request the Android INTERNET permission, so the operating system will not let it open a network connection at all — not for analytics, not for crash reports, not for anything. You can confirm this yourself in the manifest or by inspecting the APK.

What Perde reads while it runs

To do its job, Perde has to look at your screen. Everything it looks at is processed in memory and discarded; none of it is written to storage and none of it is sent anywhere.

  • Screen images. Captured through the accessibility service's screenshot API (or, as a fallback on older devices, MediaProjection). Each frame is scaled down, classified by a neural network that runs entirely on your phone, and then released from memory. Frames are never saved.
  • On-screen text. Read from Android's accessibility tree. This is how Perde still works in private/incognito tabs, where screenshots are blocked. The text is scored and discarded within the same analysis pass. It is never saved, logged, or transmitted.
  • The package name of the app in the foreground. Used to decide whether to run at all, so Perde can stay idle — and save battery — while you are not in a monitored app.

What Perde stores on your device

Only two things, both in Android's app-private preference storage (perde and perde_diag), readable by no other app:

  • Your settings — language, message profile, sensitivity level, and whether protection is meant to be on.
  • Diagnostic counters — numbers shown in the app's own "Diagnostics" panel, such as the last score, when the detection loop last ran, and how many frames were analysed.

No screenshots, no screen text, no browsing history, and no record of what was blocked or when. All of it is removed when you uninstall the app.

What Perde sends

Nothing. There is no analytics SDK, no crash reporter, no advertising, no third-party library that phones home, and no server operated by this project. Perde is deliberately free of ads: an advertising SDK inside an app that can read your screen would transmit device identifiers on every request, which would contradict the only promise this app makes.

The one link that leaves the app

The Contribute button opens github.com/sponsors/crucio4 in your browser, and only when you tap it. From that point you are on GitHub's website, under GitHub's privacy statement, not this one. Perde itself does not see or receive anything about that visit.

Permissions, and why each one exists

  • Accessibility service — reads on-screen text and captures the screen without a recording indicator. This is the core of the app; without it there is no protection in private tabs.
  • Display over other apps — draws the full-screen block overlay.
  • Usage access — reports which app is in the foreground.
  • Foreground service & notifications — keeps detection alive and shows the ongoing notification Android requires.
  • Run at startup — restores protection after a reboot.

Perde requests no access to contacts, location, microphone, camera, call logs, SMS, files, or photos.

Children

Perde has no accounts and collects no data from anyone, of any age. Nothing is transmitted, so nothing about a child — or an adult — can be collected, profiled, or shared.

This website

This site is static and hosted on GitHub Pages. It sets no cookies and runs no analytics. It loads a web font from Google Fonts, which means your browser makes a request to Google's servers and Google may log your IP address as part of serving that file. No other third party is contacted.

Verify any of this

Perde is open source under the GPL-3.0 licence. Every claim above can be checked against the code at github.com/crucio4/perde-app. Copyleft also means a modified version cannot be redistributed as closed source, so a fork that quietly adds tracking cannot hide.

Changes

If this policy changes, the updated version will be posted on this page with a new effective date.
